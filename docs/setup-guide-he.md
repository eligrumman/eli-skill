# מדריך התקנה — הרצת אייג'נטים של Claude Code מהטלפון

מדריך מלא מאפס לסטאפ ש-**eli** מקים בשבילכם: שרת בענן שמריץ צי של אייג'נטים של Claude Code, נגיש מכל מקום דרך Tailscale, ונשלט מטלפון אנדרואיד דרך Termux. בלי בוט, בלי דמון מותאם — רק SSH ו-Claude Code.

> **כל הזרימה בשורה אחת:**
> טלפון (Termux) → `ssh mac` → `claude agents` → מסך אחד עם כל הסשנים בכל הפרויקטים שלכם → מתחברים לזה שרוצים וממשיכים לעבוד.

כל כתובות ה-IP, שמות המשתמש וה-hostnames למטה הם placeholders כמו `<SERVER_IP>`, `<USER>`, `<TAILNET_IP>`. תחליפו בשלכם.

> **חדשים בכל זה? התחילו כאן — מילון בשפה פשוטה.** המדריך מניח שאתם מכירים את Claude Code ותו לא. כל מונח מוסבר שוב במקום שבו הוא מופיע לראשונה, אבל הנה כולם במקום אחד:
> - **Server (שרת)** — מחשב שרץ 24/7 כדי שהאייג'נטים שלכם לא ייעצרו לעולם. או **Mac שבבעלותכם** (מחובר לחשמל וער) או מחשב ש**אתם שוכרים מ-Hetzner** (חברה שמשכירה מחשבים בדאטה-סנטר בכמה דולרים לחודש).
> - **Terminal / command line (טרמינל / שורת פקודה)** — חלון טקסט שבו מקלידים פקודות במקום ללחוץ על כפתורים.
> - **SSH (Secure Shell)** — הדרך הסטנדרטית והמוצפנת לפתוח שורת פקודה *על מחשב אחר* דרך האינטרנט. `ssh mac` פירושו "פתח לי שורת פקודה על השרת שלי".
> - **SSH client app (אפליקציית SSH)** — האפליקציה בטלפון שדרכה מריצים SSH. **אנדרואיד → Termux** (או Termius); **אייפון → Termius**. (מוסבר עם קישורי הורדה בשלב 2.)
> - **SSH key (מפתח ציבורי / פרטי)** — התחברות בלי סיסמה. יוצרים **זוג מפתחות**: המפתח **הפרטי** נשאר סודי על המכשיר, המפתח **הציבורי** מועתק לשרת. כל מי שמחזיק במפתח הפרטי התואם יכול להתחבר, אז לעולם אל תשתפו אותו.
> - **Tailscale / VPN** — רשת פרטית שמאפשרת לטלפון להגיע לשרת מכל מקום, בלי לחשוף אותו לאינטרנט הציבורי. (מוסבר בשלב 3.)
> - **Tailnet** — רשת ה-Tailscale הפרטית שלכם: כל מה שמחובר לאותו חשבון Tailscale, נגיש דרך כתובת ה-`100.x.y.z` שלו.
> - **VNC / Screen Sharing** — לראות ולשלוט בשולחן העבודה האמיתי של השרת מרחוק, למקרים ששורת פקודה לא מספיקה (התחברות בדפדפן, אפליקציית GUI).
> - **`claude agents`** — הפקודה של Claude Code שמציגה את *כל* הסשנים הרצים שלכם, בכל הפרויקטים, במסך אחד. נקודת הכניסה היומית שלכם.

## 0. מה בונים

שלושה מכשירים, tailnet אחד:

| מכשיר | תפקיד |
|---|---|
| **שרת בענן** (Hetzner) | מריץ את האייג'נטים 24/7. סוס העבודה האמיתי. |
| **Mac** (אופציונלי) | תיבה always-on שנייה / מכונת פיתוח, גם היא על ה-tailnet. |
| **טלפון אנדרואיד** (Termux) | השלט רחוק שלכם. מתחברים ב-SSH מכל מקום. |

הכל מחובר יחד ע״י **Tailscale** (VPN פרטי בלי הגדרות), כך שכל מכונה מגיעה לכל מכונה אחרת דרך IP פרטי יציב — בלי port-forwarding, בלי לחשוף SSH לאינטרנט הציבורי.

## בחירת המכונה: Mac מול Hetzner

לפני שמקימים משהו, החליטו איפה האייג'נטים יגורו. שתי אפשרויות כנות:

| | **Mac** (MacBook ישן / Mac Mini שכבר יש לכם) | **Hetzner** (שרת ענן לינוקס) |
|---|---|---|
| עלות | **חינם** — חומרה שלכם, בלי תשלום חודשי | החל מ-€6.80 לחודש (≈ $7.50) ועד €16.40 לחודש (≈ $18) |
| זמינות | תלויה ברשת הביתית ובחשמל שלכם; אתם מי ששומר עליו חי | בנוי לזמינות: מהירות גבוהה יותר, יציבות טובה יותר, ובלתי תלוי ברשת הביתית שלכם |
| הכי מתאים ל | אפליקציות שקיימות רק ב-Mac; GUI/דפדפן על המכונה | לולאות always-on / אייג'נטים שאסור שייפלו ולא צריכים להיות תלויים באינטרנט או בחשמל של הבית |

**שתי האפשרויות תקפות, והרבה אנשים מריצים את שתיהן:** לינוקס/Hetzner לצי ה-always-up, ו-Mac לעבודת GUI/דפדפן/אפליקציות Mac. בחרו לפי מה שאתם צריכים.

**מה כדאי לי לבחור?** רוצים צי always-on של הקם-ושכח שלא תלוי בבית? לכו על **Hetzner**. כבר יש לכם Mac ורוצים תיבה חינמית שגם אפשר לראות את המסך שלה (GUI, דפדפן, אפליקציות Mac)? הריצו על ה-**Mac** — רק הפעילו Remote Login ושמרו אותו מחובר לחשמל וער (ראו "הרצת השרת על Mac" למטה).

## 1. הקמת השרת (Hetzner Cloud)

> **תעשו קודם את שני הדברים האלה:** (1) **Hetzner דורשת אימות זהות** לפני שאפשר ליצור שרתים — העלו דרכון או תעודת זהות בדף האימות שלהם. זה יכול לקחת כמה שעות, אז התחילו עכשיו. (2) מסך היצירה מבקש להדביק **מפתח ציבורי (public key)** של SSH — אז קפצו לשלב 2, צרו את המפתחות, וחזרו לכאן. (המפתח שאתם מדביקים ביצירה מותקן עבור משתמש ה-**root**; שלב ה-`authorized_keys` הידני בשלב 2 מיועד למשתמש הלא-root שתיצרו למטה, או להוספת מפתחות נוספים בהמשך.)

1. פותחים חשבון ב-[Hetzner Cloud](https://www.hetzner.com/cloud) → פרויקט חדש → **Add Server**.
2. תיבה מומלצת: **CX42** — 8 vCPU, 16GB RAM, 160GB SSD, בערך €16.40 לחודש (≈ $18). מריץ בנוחות **30+** סשנים של Claude Code במקביל. (תיבת הכניסה הזולה יותר **CX32** — 4 vCPU, 8GB RAM, 80GB SSD, בערך €6.80 לחודש ≈ $7.50 — מריצה בנוחות **~10–20**.) קו ה-CX של Hetzner הוא CX22 / CX32 / CX42 / CX52. ראו את הערת הקיבולת למטה — RAM כמעט אף פעם אינו המגבלה האמיתית.
3. **Image:** Ubuntu 24.04 LTS.
4. **SSH key:** הדביקו כאן עכשיו את המפתח הציבורי של הטלפון *וגם* של ה-Mac (ראו שלב 2) כדי להתחבר בלי סיסמה. אפשר גם להוסיף מפתחות מאוחר יותר.
5. צרו. שמרו את ה-**public IPv4** — זה ה-`<SERVER_IP>` שלכם.

> **כמה אייג'נטים זה באמת יכול להריץ?** הרבה יותר ממה שנדמה לכם. על Mac עם 32GB הבעלים הריץ **35 סשנים של Claude Code בו-זמנית** — כל אחד נע בין ~65MB (במנוחה) ל-~740MB (בעבודה פעילה), **חציון ~320MB, ממוצע ~367MB RSS** — *RSS (resident set size) הוא הזיכרון שתהליך באמת מחזיק ב-RAM* — ו-RSS סופר-יתר על המידה זיכרון framework משותף, כך שהעלות התוספתית האמיתית לכל סשן נוסף נמוכה יותר. כלל אצבע: סשן **במנוחה** הוא ~50–150MB; סשן **שעובד קשה** כמה מאות MB. אז **CX32 (8GB) מריץ בנוחות ~10–20 סשנים; CX42 (16GB) מריץ 30+** (בקירוב).
>
> **RAM כמעט אף פעם אינו המגבלה האמיתית.** התקרות האמיתיות הן (1) ה-**מכסה / rate limits של המנוי שלכם ל-Claude** — כל סשן מחויב בנפרד — ו-(2) CPU בזמן פרצי עבודה כבדים בו-זמניים. בחרו את התיבה הזולה ביותר שמתאימה לתקציב שלכם; תגיעו למגבלות התוכנית שלכם ב-Claude לפני שייגמר לכם הזיכרון.

התחברות ראשונה והקשחה:
```bash
ssh root@<SERVER_IP>

# צרו משתמש לא-root שתעבדו איתו בפועל
adduser <USER>
usermod -aG sudo <USER>

# העתיקו את מפתח ה-SSH מ-root למשתמש החדש
rsync --archive --chown=<USER>:<USER> ~/.ssh /home/<USER>

# firewall בסיסי
ufw allow OpenSSH
ufw enable

# עדכוני אבטחה אוטומטיים (מומלץ לתיבת always-on)
sudo apt install unattended-upgrades
```

**כיבוי התחברות root וסיסמה — המלכוד של Ubuntu 24.04.** עריכה של `/etc/ssh/sshd_config` בלבד **לא** עובדת על ה-image של Hetzner: הוא מגיע עם `/etc/ssh/sshd_config.d/50-cloud-init.conf` שמכיל `PasswordAuthentication yes`, וה-drop-in הזה גובר על הקובץ הראשי. הוסיפו drop-in משלכם שגובר (הקבצים נטענים לפי סדר, אז `99-` מנצח את `50-`):
```bash
sudo tee /etc/ssh/sshd_config.d/99-hardening.conf <<'EOF'
PasswordAuthentication no
PermitRootLogin no
EOF
sudo systemctl restart ssh
```

> ⚠️ **לפני שאתם סוגרים את סשן ה-root, ודאו שהתחברות עם מפתח בלבד עובדת בטרמינל שני:** `ssh <USER>@<SERVER_IP>` ואז `sudo whoami` אמור להדפיס `root`. רק אחרי שהסשן החדש עובד תתנתקו מ-root — אחרת טעות הקלדה יכולה לנעול אתכם לגמרי מחוץ לתיבה.

## 2. מפתחות SSH (טלפון + Mac → שרת)

**קודם — האפליקציה שדרכה תקלידו פקודות בטלפון.** SSH צריך *אפליקציית client* בטלפון. בחרו לפי פלטפורמה:

- **Termux (אנדרואיד)** — **אפליקציית טרמינל חינמית לאנדרואיד**: היא נותנת לכם שורת פקודה של לינוקס ישירות על הטלפון, ושם מקלידים `ssh` כדי להגיע לשרת. אנדרואיד בלבד. הורדה מ-[Google Play](https://play.google.com/store/apps/details?id=com.termux) — זמין גם ב-[F-Droid](https://f-droid.org/packages/com.termux/) וב-[GitHub releases](https://github.com/termux/termux-app/releases).
- **Termius (אייפון ואחרים)** — **client של SSH עם GUI ידידותי**: במקום להקליד פקודות, שומרים את השרת כחיבור ומקישים כדי להתחבר. חוצה-פלטפורמות — **iOS, Android, Mac, Windows**. זו הבחירה ל**משתמשי אייפון** (Termux הוא אנדרואיד בלבד). הורדה: [Apple App Store](https://apps.apple.com/app/termius-ssh-client/id549039908).

**בקצרה: אנדרואיד → Termux (או Termius); אייפון → Termius.** הפקודות למטה מוצגות עבור Termux; ב-Termius מזינים את אותם מפתחות/host דרך ה-GUI.

הכלל: **המפתח הפרטי (החצי הסודי של ההתחברות שלכם) אף פעם לא עוזב את המכשיר; מעתיקים את המפתח *הציבורי* לשרת.**

**בטלפון (Termux):**
```bash
pkg install openssh          # פעם ראשונה בלבד
ssh-keygen -t ed25519        # קבלו את ברירות המחדל; הוסיפו passphrase אם תרצו
cat ~/.ssh/id_ed25519.pub    # העתיקו את השורה הזו
```

**ב-Mac:**
```bash
ssh-keygen -t ed25519        # אם עוד אין לכם
cat ~/.ssh/id_ed25519.pub    # העתיקו גם את זה
```

**באייפון (Termius) — תת-הזרימה ליצירת מפתח.** ל-Termius אין שורת פקודה, אז יוצרים את המפתח ב-GUI שלו: פתחו **Termius → Keychain → + (New Key) → Generate**, בחרו **Ed25519**, ושמרו. הקישו על המפתח → **Copy Public Key** (זה החצי שהולך לשרת). אחר כך **Hosts → + (New Host)**: קבעו **Address** ל-`<TAILNET_IP>` (או `<SERVER_IP>` בהתחלה), **Username** ל-`<USER>`, ותחת **Keys** צרפו את המפתח שיצרתם. הקישו על ה-host כדי להתחבר — בלי סיסמה.

**בשרת**, הוסיפו את שני המפתחות הציבוריים:
```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys   # הדביקו כל pubkey בשורה נפרדת
chmod 600 ~/.ssh/authorized_keys
```

**אלטרנטיבה בפקודה אחת — `ssh-copy-id`.** כל עוד התחברות עם סיסמה עדיין מופעלת, מה-Mac או מ-Termux אפשר להתקין pubkey בפקודה אחת במקום לערוך `authorized_keys` ידנית:
```bash
ssh-copy-id <USER>@<SERVER_IP>
```

אם ה-Mac והשרת צריכים גם להתחבר זה לזה ב-SSH, חזרו על אותו דבר: צרו מפתח ב-Mac, הוסיפו את ה-pubkey שלו לשרת (ולהיפך). זה בדיוק שלב "pubkey על ה-Mac + על שרת ה-Hetzner".

## 3. Tailscale (להגיע לשרת מכל מקום)

כתובות IP ציבוריות משתנות וחושפות אתכם; Tailscale נותן לכל מכונה IP פרטי יציב על ה-tailnet שלכם.

### מה זה Tailscale ואיך הוא עובד?

Tailscale היא אפליקציה חינמית שמחברת בין המכשירים שלכם — הטלפון, ה-Mac, השרת — דרך חיבור פרטי ומאובטח, כאילו כולם על אותו ה-Wi-Fi הביתי, גם כשהם במקומות שונים. מתקינים אותה על כל מכשיר ומתחברים עם **אותו חשבון** בכולם. מה זה נותן:

- כל מכשיר מקבל **כתובת פרטית משלו** (זה נראה כמו `100.x.y.z`) שרק המכשירים האחרים שלכם יכולים להגיע אליה. כך הטלפון מתחבר לשרת מ**כל מקום** — Wi-Fi בבית קפה, נתונים סלולריים — **בלי לגעת בהגדרות הראוטר ובלי לחשוף את השרת לאינטרנט הציבורי**.
- **MagicDNS** (הפעילו אותו ב-Tailscale) מאפשר להשתמש בשם קל כמו `mac` במקום המספר.

**בשרת:**
```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
# פתחו את ה-URL שמודפס, התחברו → השרת מצטרף ל-tailnet שלכם
tailscale ip -4    # שמרו את זה -> <TAILNET_IP> של השרת
```

**ב-Mac:** התקינו את אפליקציית Tailscale (או `brew install tailscale`), התחברו עם אותו חשבון.

**בטלפון:** התקינו **Tailscale** מ-Play Store, התחברו עם אותו חשבון, הפעילו **on**.

עכשיו כל מכשיר מגיע לשרת ב-`<TAILNET_IP>` בלי קשר לרשת. הערות מהניסיון:
- ה-tailnet IP נפתר רק כש-Tailscale **up** בשני הצדדים. אם זה מקרטע, שמרו את ה-`<SERVER_IP>` הציבורי כגיבוי.
- אם אתם רוצים להגיע לתיבה לפי שם, הפעילו **MagicDNS** בקונסולת הניהול של Tailscale.

### מלכודות Tailscale וטעויות נפוצות של מתחילים

**כללי**
- **אותו חשבון על כל מכשיר.** הטעות מספר 1: השרת מחובר לחשבון Tailscale אחד והטלפון לחשבון אחר, ולכן הם לא רואים זה את זה. כל המכשירים חייבים להיות על אותו tailnet (או משותפים אליו במפורש).
- **Tailscale חייב להיות ON בשני הקצוות** בזמן ההתחברות. אם `ssh mac` נתקע, בדקו ש-Tailscale באמת up בטלפון **וגם** בשרת.
- **פקיעת מפתח (key expiry).** כברירת מחדל מפתח של מכשיר פוקע (בערך אחרי 180 יום) והמכשיר נושר בשקט מה-tailnet עד שתאמתו מחדש. לשרת always-on, **בטלו את פקיעת המפתח** למכונה הזו בקונסולת הניהול כדי שלא יינשור לעולם.
- השתמשו ב-IP של `100.x` ישירות, או הפעילו **MagicDNS** לשמות. שמרו את ה-**IP הציבורי של השרת כגיבוי** לזמנים שה-tailnet מקרטע.

**שרת לינוקס**
- אחרי ההתקנה, `sudo tailscale up`; ודאו שהשירות עולה אוטומטית באתחול (`sudo systemctl enable --now tailscaled`).
- **אימות headless:** אין דפדפן בשרת → הוא מדפיס URL להתחברות; פתחו אותו בטלפון/לפטופ כדי לאשר. או ספקו לא-אינטראקטיבית עם auth key: `sudo tailscale up --authkey tskey-...`.
- אל תחסמו ב-firewall את ה-interface של `tailscale0` אם אתם מריצים ufw/iptables.
- (אופציונלי) `tailscale up --ssh` מפעיל SSH מנוהל ע״י Tailscale; לא נדרש אם אתם כבר משתמשים ב-SSH מבוסס-מפתח.

**Mac**
- שני סוגים: אפליקציית **Mac App Store** מול האפליקציה **standalone/open-source** (או `brew install --cask tailscale`). ל-Mac שמשמש כ*שרת*, העדיפו את גרסת ה-standalone כדי לקבל את ה-CLI של `tailscale`.
- בהפעלה ראשונה macOS מציג **בקשת הרשאה ל-VPN / network-extension** — חייבים לאשר אותה, וזה דורש את המסך (עשו זאת דרך גישה פיזית או Screen Sharing פעם אחת).
- ודאו ש-Tailscale **עולה בהתחברות (launch at login)** (במיוחד ב-Mac headless עם התחברות אוטומטית), ושאפליקציית שורת התפריטים מחוברת.
- אל תשאירו בטעות **"Use exit node"** דלוק — הוא מנתב את כל התעבורה שלכם דרך מכשיר אחר, וזה איטי ומבלבל.

**נייד (אנדרואיד)**
- Tailscale הוא **אפליקציה נפרדת** מ-Termux — התקינו, התחברו, הפעילו ON. Termux עצמו לא מריץ Tailscale.
- **אופטימיזציית סוללה של אנדרואיד יכולה להרוג את ה-VPN.** החריגו את Tailscale מאופטימיזציית הסוללה כדי שיישאר מחובר ברקע.
- **אחרי אתחול (reboot) של הטלפון, Tailscale עלול לחזור כבוי (OFF).** כשהטלפון מופעל מחדש (או עדכון מערכת מאתחל אותו), מתג ה-VPN לרוב חוזר לכבוי — אז `ssh mac` פשוט נתקע עד שתפתחו מחדש את אפליקציית Tailscale ותדליקו אותה בחזרה ל-ON. כדי להימנע מזה, הפעילו את האופציה **"Connect on start / run on boot"** בהגדרות אפליקציית האנדרואיד (והחריגו אותה מאופטימיזציית הסוללה). כלל אצבע: אם אתם לא מצליחים להגיע לשרת מיד אחרי הפעלה מחדש של הטלפון, בדקו ש-Tailscale דלוק קודם — זו הסיבה הנפוצה ביותר.
- היזהרו עם **"Always-on VPN" / "Block connections without VPN"** של אנדרואיד — בדרך כלל השאירו את אלה כבויים; פשוט הדליקו את Tailscale כשצריך.
- אם שם MagicDNS לא נפתר או `ssh mac` נכשל בזמן קצוב בנייד: הדליקו/כבו את Tailscale, או שאתם מאחורי Wi-Fi עם captive-portal → חזרו ל-IP הציבורי.

**פקודות דיבאג (כל פלטפורמה)**
- `tailscale status` — מציג peers והאם החיבור **ישיר או relayed**.
- `tailscale ping <host>` — בודק קישוריות ל-peer.
- `tailscale netcheck` — מאבחן תנאי NAT/relay.

## 4. קיצור "mac" ב-Termux (הארגונומיה בצד הטלפון)

הטריק שמזרז הכל: host מוגדר בשם, כך שתקלידו `ssh mac` במקום פקודה מלאה.

ב-Termux, ערכו את `~/.ssh/config`:
```
Host mac
    HostName <TAILNET_IP>        # או <SERVER_IP> כגיבוי
    User <USER>
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60       # שומר על הסשן מלהתנתק ברשת סלולרית
    ServerAliveCountMax 3
```

עכשיו מהטלפון: `ssh mac` → אתם בשרת. (תקראו לזה איך שתרצו — "mac", "server", "fleet".)

שיפורי חיים אופציונליים ב-Termux:
- `pkg install openssh mosh` — **mosh** שורד שינויי רשת / קליטה חלשה הרבה יותר טוב מ-SSH רגיל לשימוש נייד. מעל Tailscale זה פשוט עובד; אם אי פעם תיפלו חזרה ל-IP הציבורי עם `ufw` דלוק, פתחו UDP **60000–61000** (`sudo ufw allow 60000:61000/udp`).
- Termux widgets מאפשרים לשים כפתור `ssh mac` בלחיצה אחת על מסך הבית.

## 5. התקנת Claude Code בשרת

## מרכז השליטה שלכם: `claude agents` (agent view)

`claude agents` פותח את **agent view** — מסך אחד שמציג את כל סשן רקע שהתחלתם, מקובץ לפי מצב (**Needs input** / **Working** / **Completed** / **Pinned**). הפכו את זה לנקודת הכניסה הראשית שלכם במקום `claude` רגיל. לפרטים מלאים קראו את [התיעוד הרשמי של `claude agents` / agent view](https://code.claude.com/docs/en/agent-view).

- **כל הפרויקטים בבת אחת.** כברירת מחדל agent view מציג סשנים בכל הפרויקטים שלכם, בלי קשר לתיקייה שממנה הפעלתם. צמצמו לפרויקט אחד עם `claude agents --cwd ~/projects/my-app`.
- **שיגור משימה (Dispatch):** הקלידו prompt ולחצו `Enter` → סשן רקע חדש מתחיל כשורה. כל `Enter` מפעיל סשן *נפרד*, כך שאפשר להריץ כמה במקביל.
- **הצצה (Peek):** בחרו שורה ולחצו `Space` כדי לראות את הפלט האחרון שלה או את השאלה שהיא מחכה לה; ענו inline עם `Enter`.
- **התחברות (Attach):** `Enter` או `→` על שורה נכנס לשיחה המלאה. **ניתוק (Detach):** `←` על prompt ריק (או `Esc`) חוזר לטבלה.
- **הכנסת סשן קיים פנימה:** הריצו `/bg` בתוך סשן `claude` רגיל (או לחצו `←`) כדי להעביר אותו לרקע ב-agent view.
- **הם שורדים ניתוקים.** כל סשן רקע ממשיך לרוץ **בלי טרמינל מחובר** — כך שאפשר לסגור את Termux/Termius או לאבד קליטה בטלפון והאייג'נטים ממשיכים לעבוד. פתחו מחדש את `claude agents` מאוחר יותר וכולם עדיין שם. זו התשובה האמיתית ל"זה לא ימות כשאתנתק?" — לא, סשני רקע נשמרים בשרת.
- **מכסה, לא RAM, היא המגבלה.** כל סשן משתמש במכסה של המנוי שלכם ל-Claude **בנפרד**, כך שזו — ולא הזיכרון — התקרה המעשית לכמה להריץ בו-זמנית (ראו את הערת הקיבולת בשלב 1).
- זהו **research preview**; קיצורי המקלדת עשויים להשתנות.

## 6. איך האייג'נטים באמת עובדים

זה החלק שחשוב. "אייג'נט" כאן הוא לא שרת מיוחד; הוא **תיקיית פרויקט + הגדרת תפקיד**. יש שני סגנונות שאני משתמש בהם.

### סגנון A — Subagent כקובץ markdown
בתוך פרויקט שמים קבצי תפקיד ב-`.claude/agents/*.md`. כל אחד הוא קובץ markdown עם YAML frontmatter; הגוף הוא מדריך ההפעלה המלא של האייג'נט (פרסונה, פקודות מדויקות, כללים). דוגמה (`.claude/agents/qa.md`):
```markdown
---
name: qa
description: MANDATORY browser-based QA verifier. Use BEFORE any claim that a UI feature works.
tools: Read, Grep, Glob, Bash
model: sonnet
---

You are the QA verifier. Open the real page in Chrome, screenshot it,
read the console, and report only observed facts — never "should work".
...מדריך הפעלה מלא...
```
Claude Code מציג אותו בבורר האייג'נטים, והסשן הראשי מפעיל אותו לפי דרישה. מצוין לתפקידים on-demand (בודק QA, reviewer).

### סגנון B — אייג'נט קבוע בצי (job + skill + prompt)
לעובדים always-on, כל אייג'נט הוא **Claude Code background job** ארוך-טווח, ש:
- **הזהות** שלו מגיעה מ-`state.json` משלו (הוא קורא את זה ראשון בכל סשן כדי ללמוד את שמו),
- **ההתנהגות** שלו מגיעה מ-**skill** באותו שם ב-`.claude/skills/<agent-name>/` (מדריך ההפעלה שלו, כולל מרווח ה-`/loop`, למשל `/loop 15m`),
- **המשימה** שלו מגיעה משורת prompt קנונית בקובץ שליטה משותף (למשל `agent_prompts.txt`).

בהפעלה כל אייג'נט: קורא את `state.json` → מחפש את משימתו → טוען *רק את ה-skill שלו* → מוודא שה-`/loop` שלו רץ → ואז פועל **רק בתחום שלו**, עם prefix של `[agent-name]` לכל commit ומסלים כל דבר מחוץ לתחום במקום לתקן אותו.

### מבנה הפרויקט שמחבר הכל
פרויקט אמיתי מבוסס-אייג'נטים (הפרויקט `investor` שלי) נראה כך:
```
project/
├── CLAUDE.md                     # "החוקה": כללים מחייבים לכל אייג'נט
├── .claude/
│   ├── agents/*.md               # subagents מסגנון A (למשל qa.md)
│   ├── skills/<agent>/           # מדריכי הפעלה מסגנון B, אחד לכל אייג'נט בצי
│   ├── settings.json             # allowlist הרשאות + denylist ל-force-push
│   └── worktrees/                # כל אייג'נט עובד ב-git worktree מבודד
├── docs/ops/                     # runbooks, fleet-constitution.md, לוגים של תקריות
└── <domain code>/                # הדבר עצמו שהאייג'נטים מפעילים
```
משמעת מפתח ששומרת על צי שפוי:
- **`CLAUDE.md` מחייב**, לא דקורטיבי — זה חוזה ההפעלה עבור האדם *וגם* כל אייג'נט.
- **הפרדת תפקידים:** אייג'נט מתאם אף פעם לא מתקן לוגיקת domain; כשל domain = prompt/skill/loop לא-מספיק-טוב, מתוקן *שם*.
- **מקור אמת יחיד:** מניפסט / קובץ prompt אחד; משימות נקראות מילה במילה, לעולם לא מועתקות.
- **worktrees מבודדים:** אייג'נטים עורכים ב-`git worktree` משלהם כדי לא להתנגש.
- **הרשאות כמעקות בטיחות:** `settings.json` מאשר פקודות בטוחות ואוסר כל וריאציה של force-push.

## 8. הרצת השרת על Mac

אם אתם משתמשים ב-Mac (MacBook ישן או Mac Mini) בתור התיבה ה-always-on במקום — או לצד — שרת ענן, כמה דברים ספציפיים ל-Mac שומרים עליו אמין. כל השאר במדריך (מפתחות SSH, Tailscale, הקיצור `ssh mac`, התקנת Claude Code) זהה; ב-macOS השתמשו ב-`brew install` היכן שהצעדים ל-Ubuntu משתמשים ב-`apt` (התקינו קודם את [Homebrew](https://brew.sh) אם אין לכם, ואז `brew install node` רק אם אתם הולכים על מסלול ה-npm ל-Claude Code).

### א) הפעילו Remote Login (קודם כל)
macOS מגיע עם שרת ה-SSH שלו **כבוי**, אז `ssh mac` נכשל עד שמפעילים אותו: **System Settings → General → Sharing → Remote Login → On**, והגבילו אותו למשתמש שלכם. ה-`~/.ssh/authorized_keys` של ה-Mac אז מקבל את המפתח הציבורי שהדבקתם בדיוק כמו שרת לינוקס — אותו קובץ, אותו `chmod 700 ~/.ssh` / `chmod 600 authorized_keys`.

### ב) שמרו אותו מחובר לחשמל
מחשב נייד שמשמש כשרת חייב להישאר **מחובר לחשמל (AC) כל הזמן** — תמיד על המטען. אף פעם אל תריצו אותו על סוללה בתור שרת: הסוללה מתרוקנת, המכונה נכנסת לשינה או נכבית, והצי שלכם הולך איתה.

### ג) אף פעם אל תתנו לו לישון
הגדירו את ניהול הצריכה כך שה-Mac לעולם לא ישן. זו התצורה המדויקת להרצה:

```
sudo pmset -a sleep 0 displaysleep 0 disksleep 0 womp 1 ttyskeepawake 1 tcpkeepalive 1 powernap 1 standby 1
```

מה עושים הדגלים המרכזיים:
- `sleep 0` — לעולם לא שינת מערכת
- `displaysleep 0` — הצג לעולם לא ישן
- `disksleep 0` — הדיסקים נשארים מסתובבים
- `womp 1` — התעוררות לגישת רשת (Wake-on-LAN / magic packet)
- `ttyskeepawake 1` — נשאר ער כל עוד סשן SSH/tty מרוחק פעיל
- `tcpkeepalive 1` — שומר על חיבורי TCP חיים במצב צריכה נמוכה
- `powernap 1` / `standby 1` — משימות רקע ממשיכות לרוץ

למשימה חד-פעמית שאפשר לתסרט, "תישאר ער בשביל המשימה הזו", השתמשו ב-`caffeinate` — למשל `caffeinate -dimsu claude ...` מחזיק את ה-Mac ער כל עוד הפקודה רצה. שימו לב שסשן SSH פעיל כבר מבקש התעוררות דרך `ttyskeepawake`, כך שביום-יום נדיר שתצטרכו אותו.

**MacBook עם המכסה סגור (clamshell):** `sudo pmset -a disablesleep 1` מאפשר ל-MacBook להמשיך לרוץ עם המכסה סגור גם בלי צג חיצוני. זה מבטל לגמרי את שינת ה-clamshell — המכונה לעולם לא תישן מסגירת המכסה — אז השתמשו בזה במודע. השארת המכסה פתוח היא האפשרות הפשוטה יותר והמתקררת יותר.

### ד) לראות את המסך מרחוק — Screen Sharing (VNC) דרך Tailscale
SSH + Claude הם היום-יום שלכם. אבל לפעמים צריך את שולחן העבודה עצמו: התחברות בדפדפן, אפליקציית GUI, דיאלוג תקוע. Screen Sharing הוא פתח המילוט הזה.

- על שרת ה-Mac: **System Settings → General → Sharing → הפעילו Screen Sharing** (או **Remote Management**). זה מגיש VNC על פורט **5900**.
- מכיוון שה-Mac נמצא על ה-tailnet שלכם, אתם יכולים להגיע למסך הזה מ**כל מקום**, לא רק מה-LAN.
- מ-Mac אחר: Finder → **Go → Connect to Server** (**⌘K / Cmd + K**) → הזינו `vnc://<TAILNET_IP>` → התחברו עם המשתמש של ה-Mac. עכשיו אתם רואים ושולטים בשולחן העבודה.

תחשבו על זה ככה: SSH + Claude הם איך שאתם עובדים כל יום; Screen Sharing הוא איך שאתם תופסים את ההגה כשאייג'נט צריך דפדפן, נתקל בשאלת GUI, או משהו ויזואלי נשבר.

### ה) התאוששות אחרי אתחול / הפסקת חשמל
תקלות חשמל ואתחולים קורים. הגדירו את ה-Mac לחזור בעצמו, ואז שגרו מחדש את האייג'נטים ידנית:

- **הפעלה אוטומטית אחרי הפסקת חשמל:**
  ```
  sudo systemsetup -setrestartpowerfailure on
  ```
  (או System Settings → Energy.) זה נתמך רק בחלק מדגמי ה-Mac — זה נכשל בהרבה מחשבי MacBook, וזה בסדר; פשוט דלגו על זה שם.
- **התחברות אוטומטית** למשתמש שלכם (System Settings → Users & Groups → Automatically log in as…) כדי שה-Mac יחזור לשולחן עבודה מחובר שנגיש ל-SSH ול-Screen Sharing בלי שמישהו יקליד סיסמה במקלדת. שימו לב: **FileVault מכבה בשקט את ההתחברות האוטומטית** — אפשר אחד או השני, לא את שניהם, אז השאירו את FileVault כבוי בתיבת שרת headless.
- אחרי שהוא חזר, **התחברו ב-SSH ושגרו מחדש את האייג'נטים ידנית**: `ssh mac` → `cd project` → `claude` (או הפעילו מחדש את ה-jobs ברקע). תשמרו את זה פשוט — לא צריך auto-relaunch עם launchd.

## מוודאים שזה עובד — בדיקת קצה-לקצה

הריצו את זה פעם אחת, לפי הסדר, כדי להוכיח שכל השרשרת חיה (שונה מהצ'ק-ליסט למעלה — זו בדיקה חיה, לא בדיקת ניירת):

1. **Tailscale:** בטלפון, `tailscale status` (או האפליקציה) מציג את כל ה-peers — שרת, Mac, טלפון — מחוברים.
2. **SSH בלי סיסמה:** `ssh mac` מתחבר ישר ל-shell **בלי בקשת סיסמה** (אימות מפתח עובד).
3. **Claude מותקן:** בשרת, `claude --version` מדפיס גרסה.
4. **agent view נפתח:** `claude agents` פותח את מסך ה-agent view.
5. **שורד אתחול:** אתחלו את הטלפון, פתחו מחדש את Tailscale, ודאו שהוא מתחבר מחדש ו-`ssh mac` עדיין עובד. (אם זה נתקע, Tailscale חזר כבוי — הסיבה מספר 1.)

אם כל החמישה עוברים, סיימתם.

## פתרון תקלות

| בעיה | פתרון |
|---|---|
| `Connection timed out` / `ssh mac` נתקע | Tailscale כבוי או פג-תוקף באחד המכשירים. ודאו שהוא **up** גם בטלפון וגם בשרת; נסו את ה-`<SERVER_IP>` הציבורי כגיבוי. |
| `Permission denied (publickey)` | בדקו ש-`~/.ssh` בשרת הוא `700`, `authorized_keys` הוא `600`, ושאתם מתחברים כמשתמש הנכון עם ה-`id_ed25519.pub` של המכשיר שלכם בתוכו. |
| `EACCES` בזמן `npm install -g` | השתמשו ב-native installer (`curl -fsSL https://claude.ai/install.sh \| bash`) או הוסיפו `sudo`. |
| `claude: command not found` אחרי התקנה | פתחו shell חדש (כדי שה-PATH ייטען מחדש), או הוסיפו את תיקיית ההתקנה ל-PATH; ואז הריצו שוב `claude`. |
| הסשן נופל בנייד | השתמשו ב-`mosh mac` במקום `ssh mac`; הוסיפו `ServerAliveInterval 60` ל-`~/.ssh/config`. |
| `uv: command not found` | `curl -LsSf https://astral.sh/uv/install.sh \| sh` |
| כתובת ה-tailnet לא נפתרת לפי שם | הפעילו **MagicDNS** בקונסולת הניהול של Tailscale. |
